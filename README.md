# Evergreen

Evergreen is a responsive digital banking demonstration with a public marketing site, member account workspace, and role-protected administration. It is independent of Wealthfront and financial institutions. Every balance, payment, card, loan, verification, and investment is simulated. Use fictional information only.

The interface uses React 19, TanStack Start and Router, TypeScript, Lucide, Radix dialogs, and custom CSS. Netlify Identity supplies authentication. Netlify Functions enforce ownership and administrator roles. Netlify Database with Drizzle stores profiles, applications, ledger entries, preferences, inquiries, wallet settings, and audit events. Netlify Blobs stores private sample uploads; a protected function serves them. Original generated photography is delivered through Netlify Image CDN.

Install dependencies with `pnpm install`. For local development, use `netlify dev --port 8889`; Identity flows require an HTTPS deployment and are not emulated locally. The platform deploy process applies the included database migration and enables Identity using the checked-in feature marker. No database credentials need to be configured in application code.

Public routes are `/`, `/aboutus`, `/contact`, `/login`, `/register`, and the added `/forgot-password`. Member routes are `/account`, `/account/profile`, `/account/summary`, `/account/transfer`, `/account/deposit`, `/account/cards`, `/account/kyc`, `/account/loan`, `/account/invest`, `/account/link-card`, and `/account/settings`. Staff routes are `/admin`, `/admin/clients`, `/admin/kycrequests`, `/admin/card-applications`, `/admin/loan-requests`, and `/admin/settings`.

New accounts receive a fictional $12,480.50 opening balance with a matching ledger entry. Transfers and investments debit the demo balance atomically. Staff approvals for loans and simulated deposits credit the balance atomically and create audit events. Repeated application reviews cannot credit funds twice. KYC approval sets account level 2. A protected detail dialog replaces the unobserved dynamic user page.

Administrator access requires an `admin` role assigned by an authorized project owner through Netlify Identity. Registration never accepts or assigns administrator roles. Role changes take effect at the next login or token refresh. The application deliberately contains no default administrator credentials.

The contact form saves inquiries in the protected staff inbox. Newsletter forms save interest records. Neither claims outbound delivery; a messaging service and consent workflow are needed for actual email campaigns. Contact details use a reserved example domain and fictional phone/address. Chat, payment processing, real wallets, card issuance, and investment performance are not connected. Card linking accepts only `tok_demo_visa`; no card numbers, CVV, or security answers are collected. Profile photos are uploaded after authentication to keep uploads ownership-protected. Only PNG/JPG/GIF images up to 5 MB are accepted; sample KYC images are private.

The recreation preserved the supplied page and workspace organization while replacing unsupported claims and inconsistent branding. It repaired reciprocal currency conversion, banking destinations, account recovery, and unexplained transfer gates. Added redirects cover the old dashboard, send-money, get-started, accounts, currencies, and admin-login paths. Public robots and sitemap files were added. Security-menu guidance, generated artwork, the staff support inbox, deposit review, and opening ledger credit were additions. Testimonials and investment scenarios are labeled fictional. The translation area is a static language indicator, with no implied translation service.

No local build, development server, typecheck, or test commands were run during creation, per the platform run instructions. Files and the generated image were reviewed directly. Deployment validation and live authentication, roles, uploads, application review, and responsive keyboard checks remain necessary before claiming end-to-end verification.
