# Evergreen project architecture

This is an independent financial demonstration on TanStack Start, React, TypeScript, and Netlify. All financial data and applications must stay explicitly simulated. Never collect real payment credentials, CVV, security answers, real identity documents, or real cryptocurrency destinations. Never add claims of regulated banking or affiliation.

`src/routes/index.tsx` renders the homepage; `src/routes/$.tsx` delegates the public/account/admin paths to the shared application. `src/routes/__root.tsx` owns document metadata and UI providers. `src/components/evergreen.tsx` contains the public shell, marketing sections, auth, and shared fields. `src/components/workspace.tsx` contains separate member and staff shells, forms, history, review dialogs, and upload controls. `src/styles.css` defines the forest-green/ivory design, dark member workspace, light admin panels, breakpoints, focus styling, and reduced motion. Radix dialogs provide keyboard focus management.

`netlify/functions/banking.mts` exposes `/api/banking/*`, validates input with Zod, verifies Identity sessions, checks admin roles on every admin operation, enforces upload ownership, and serves private images with no-store headers. All mutations verify request origin. Do not move private data into the browser or trust client-side role checks. Unauthorized visitors may receive route shells but never account or staff records.

`db/schema.ts` defines structured state. `db/index.ts` constructs the Netlify Drizzle adapter inside request handling. Drizzle packages must remain on the beta line for this adapter. `drizzle.config.ts` sends migrations to `netlify/database/migrations`; generate a named migration whenever schema changes. Use database transactions for balance updates, ledger creation, application review, and audit records. Amounts in balances and ledger are integer cents; application amounts are USD values converted to cents at the mutation boundary. Guard balance debits with an atomic sufficient-funds condition and review updates with a pending-status condition.

Netlify Blobs holds uploaded binary images only. Do not use browser storage, local files, or Blobs for persistent structured application data. Profiles contain notification preferences. Email delivery is deliberately not connected. Staff wallets accept only DEMO_ addresses. The original generated marketing image is `public/img/evergreen-home.png`, served via Netlify Image CDN. `scripts/generate-image.mjs` documents its generation; it must never print credentials.

Netlify Identity must remain enabled through its feature marker. Do not create a default admin or allow role selection during registration. Authorized owners assign admin roles outside this app; changed roles apply at the next login/token refresh. Auth callbacks support confirmation, recovery, invitations, and provider login. Settings determine enabled providers and signup availability.

Prefer small edits to the existing components, accessible associated labels, clear error states, explicit simulation consent, and mobile layouts. Keep forms and server validation aligned. Never claim live message delivery, money movement, investment performance, or card issuance. Run checks only when the current platform instructions permit them; this creation run prohibited local validation commands and relied on automatic deployment validation. See README for route coverage and known integration limits.
